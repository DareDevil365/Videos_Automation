## Current implementation

The local pipeline researches readable sources, asks Gemini for a JSON script, synthesizes narration, generates timed chat/lesson graphics, binds actual footage to a layout, exports MP4/captions/cover, checks the export and prepares publication metadata. Every stage saves its results. Imported briefs/scripts work without Gemini and are labelled `provided_script`.

Two profiles exist: entertainment and education/productivity. Format contracts include `chat`, `lesson`, `clip`, `aura` and `cutout`. Narrated stock and three-block layouts also work. The agreed education scope is useful AI, study/confidence, jobs/skills and accessible knowledge; technical Python demos were rejected as channel prototypes. An explicit clip request preserves original speech, optionally above gameplay. Registered-source ingestion and transcript-based selection now exist; arbitrary movie downloading and permission inference do not.

OAuth, resumable publishing, owned Analytics, local supervision and growth reports are implemented adapters. Gemini live research, writing and evidence review have completed, followed by real local speech/export. The owner confirmed free-tier use with billing disabled. A selected key stays in ignored local configuration; no quota-driven rotation is enabled. YouTube OAuth is not connected and publication remains disabled. The latest voice was accepted; earlier script/repeated-visual prototypes were rejected. The first program-run ASMR/mystery/aura batch exported but was creatively rejected. The newer playbook path and limitations are described below; technically valid exports are not automatically good stories. Real Google browser generation remains unverified.

## Architecture and technology choices

### Repository-inspired additions (2 November 2026)

Implemented locally, without copying unlicensed repository code or adding a rendering service:

- `scene_blocks.py` extends the editing dictionary with **comparison**, **process** and **callout** scenes. Gemini selects trusted JSON parameters; Pillow creates antialiased plates and FFmpeg reveals them within measured narration time. Enable with `motion_graphics: true` on an `education_demo` request. Scene `graphic` has `kind`, `title`, and `labels`. Comparison takes two labels, process two to four, callout one. Labels must quote actual script/on-screen phrases; comparisons can quote an earlier unit, with source unit IDs recorded in the visual artifact. Titles quote the script or use a small fixed UI vocabulary. The director's schema enumerates available phrases. Blocks do not generate arbitrary Python/TSX or manufacture screenshots. The main panel must be at least 720 pixels high. This initial implementation is animated typography, not full character rigging or a replacement for relevant footage.
- `visual_review.py` sends **actual sampled images** through the existing Gemini client. Source checks compare selected media against its visual query, role and narration; video checks use beginning/middle/end samples of the selected range. Finished checks sample up to twelve spoken units, including opening/payoff frames. The saved contact sheets, explanations and input fingerprints identify what was inspected. A model cannot count an uninspected plan as a visual pass. The request setting `visual_review` is `off`, `report` or `required`; legacy/direct requests default to off unless configured. Newly initialized playbook batch requests default to required; existing immutable jobs are unchanged. Required mismatch/unknown/malformed replies hold the job. Provider failures and quotas remain holds in either enabled mode. Report-mode visual failures also prevent publication readiness. No retry rotates keys or switches to a paid provider.
- `writer.Gemini.generate(..., images=[...])` supports bounded inline JPEG previews: at most eight images, downscaled to 1600 pixels, with metadata removed during re-encoding and a total encoded-size limit. Image bytes are included in cache identity. These are multimodal inputs to the configured model, not paid image generation. They share the same free-project check, daily local budget and provider cooldown as writing. No personal browser/account is involved.
- For factual playbooks, **evidence review and directing now share one model call**, with separate required evidence and creative verdicts. Unsupported evidence still stops production. Non-playbook factual scripts retain the existing separate evidence reviewer. The script schema fixes the fiction boolean to the brief and excludes fiction-labelled units in a factual instructional episode; explicitly hypothetical examples must remain instructional examples, not invented testimonials.
- `media_library.py` and CLI `library-index` / `library-search` provide a rebuildable SQLite full-text index over registered media descriptions/titles/queries. Search returns candidates and rechecks asset integrity/expiry/eligibility. It does not scan arbitrary personal files, classify pictures, infer licenses or automatically bind a top result to narration. This deliberately small first step avoids another model/dependency before its usefulness is measured.

The existing flow now includes `visuals -> source-frame review -> direct -> render -> finished-frame review -> technical QA -> package`. Review JSON and contact sheets are copied beside batch exports under `visual-review/`; normal checkpoint hashing protects their referenced artifacts. Required-review errors preserve partial work, and retries reuse valid upstream checkpoints and content-bound model caches. No automatic creative repair is claimed: unsupported visual edits, missing essential footage, unknown judgements and mismatches require a deliberate change/retry. The existing bounded script/director structural repairs remain.

These choices were inspired by the actual-frame loop in Code2Video-AI, the narration-aware media checks in OpenReels and the structured scene approaches in ShowLab Code2Video/Scenerio. We retained Python/Pillow/FFmpeg to reuse existing voice timing, captions, queue and deployment. Remotion/Manim remain possible later adapters; native dependencies and arbitrary generated-code execution are unnecessary for these initial blocks. See [the deep audit](research/repositories/GEMINI_VIDEO_REPOSITORY_DEEP_DIVE.md) for source links and license findings. Retention, humor and copyright conclusions are not established by a model pass. Audio/music suitability is not inspected by the frame reviewer; intervening motion and unsampled units can be missed.

Standalone demonstration: `run_upgrade_demo.cmd` resumes `Resources/Plans/repo-upgrade-final.json`. Its original script/director use Gemini, voice/alignment/rendering stay local, and the finished-frame check uses the same configured Gemini API. It uses a saved, dated public interview-guidance excerpt and original hypothetical sample wording. The prototype is test-only and cannot publish. `tools/create_upgrade_demo.py` creates that plan on a fresh checkout if absent, fetching a fresh source excerpt; it refuses to overwrite an existing immutable plan. Free-tier availability and configured local call budgets can still hold a run.

## Requests, checkpoints and recovery

`topic + sources / imported brief â†’ research.json â†’ script.json â†’ voice.json â†’ visuals.json â†’ direct.json + compose-job.json â†’ render.json â†’ quality.json â†’ package.json`

State is in `data/pipeline/pipeline.sqlite3`, settings in `config.json`, copied media in `media/assets/`, and each immutable request/results in `jobs/<job-id>/`. Checkpoints and referenced media have hashes. Changed artifacts hold rather than silently alter the edit. Resetting a failed downstream stage preserves completed upstream work and invalidates publication approval. Exact duplicate scripts across jobs hold.

Production uses a renewable global media lease plus job leases. A dead worker's expired lease can be reclaimed; a second active worker is rejected. The browser has one background executor; the CLI can work without a browser. Avoid simultaneous manual compositor exports on a constrained PC. Cancellation is checked between stages and during render heartbeat; a pending model request may finish first. Low disk holds production. Incomplete render work is retained for inspection; arbitrary cleanup/deletion is not automatic.

Narrated jobs assemble measured speech once, mute footage speech and add optional registered music. Source-clip jobs use exact `clip_asset_id`, `clip_start`, `clip_end`; original speech is preserved. Captions can come from validated supplied cues, imported subtitles or local ASR. Real timed burn-in has a tested output manifest and retained clean render. No route currently guarantees perfect word alignment or transcription accuracy.

Source route: registered work/episode and permission -> ingest -> subtitles/ASR -> real cue selection -> bounded clip job -> normal production. Generation route: prompt job -> provider preflight -> one submission -> download/import -> registered asset -> normal production. Generation dependencies can hold a production job until its asset arrives.

## Publication and supervision

`publish` alone is a network-free payload preview. `approve` binds a ready, non-test video to its exact checked media/metadata. `publish --apply` additionally requires an explicitly enabled private/scheduled profile and matching OAuth identity. Scheduled jobs need a future timezone-bearing `publish_at`. Immediate-public mode is not offered. Optional owner-enabled `auto_private_upload: true` lets the worker approve technically eligible finished versions and upload privately under that configured policy; it is off by default.

Session URLs/tokens are private local state and excluded from dashboard responses. Lost completion responses are resolved by querying the existing session. Expired/unknown sessions hold for reconciliation. Jobs with an upload record cannot reset content; create a new changed-content job. The software does not delete videos or submit disputes/counter-notices. Removing a video does not clear a strike. Ordinary Data API access is not a complete copyright-claims/strikes feed: check official Studio notices and record an incident to pause the affected channel. Alerts currently remain in the local database/dashboard, with no external message sending.

## Free-only controls and evidence limits

Gemini uses the explicitly checked free text route `gemini-3.5-flash-lite`, structured output and no paid grounding/tools/fallback. Recheck [official pricing](https://ai.google.dev/gemini-api/docs/pricing) when changing models. Local budgets supplement provider limits; they cannot prevent charges on a wrongly configured billed project. There is no key/project rotation to evade quota. Missing keys, denied access and quotas hold/retry. Public pages requiring login/paywalls/JavaScript or missing transcripts may not be readable.

Quota handling now stores a shared Gemini cooldown in SQLite, across both channels and process restarts. An HTTP 429 honors `Retry-After` and Google's `RetryInfo`; absent a longer hint, repeated quota responses back off from one minute to at most one hour. An explicit daily-quota violation conservatively holds for 24 hours (or longer when instructed), rather than guessing an earlier reset. Cached successful responses remain usable during cooldown, and queued work resumes with completed upstream stages preserved. Success clears the failure backoff. Hitting the separate local daily budget waits until the next UTC midnight. `doctor` reports local call counts, remaining local budget and cooldown; those are not the provider's actual balance.

This retains one selected key: [Google applies rate limits per project rather than per API key](https://ai.google.dev/gemini-api/docs/rate-limits). The provider's daily reset is midnight Pacific; the local budget's UTC reset is deliberately a separate accounting rule. These controls reduce avoidable failures and repeated requests; they cannot promise unlimited free production. No additional supplied keys are copied for quota circumvention.

Validation of this update used simulated HTTP 429s: shared cooldown across workspace reopen, retry hints/daily classification, cache access during cooldown, escalating waits, successful reset and local usage status. The combined production/FFmpeg/HTTP run passed 41 tests in 13.46 seconds; the final targeted contract/recovery run passed all 38 tests in 3.40 seconds. No additional live generation calls were used for quota tests.

The installed voice's [model card](https://huggingface.co/rhasspy/piper-voices/raw/main/en/en_US/ljspeech/high/MODEL_CARD), [author statement](https://brycebeattie.com/files/tts/) and [dataset](https://keithito.com/LJ-Speech-Dataset/) are recorded locally with exact model/config hashes. Other voices require their own evidence. Software/runtime licenses still apply when redistributing. Kokoro voice setup and local auditions have since been added. The current English male voice was accepted in a prototype; multilingual quality and per-character direction remain unvalidated.

Asset declarations/evidence are recorded, not independently certified. Lack of previous claims is not permission or a YPP guarantee. Gameplay, resizing or adding music/chat does not by itself establish originality. Music selected inside YouTube's app is not automatically licensed for an external FFmpeg export. Only supplied/explicitly licensed local inputs are used by the editor.

[Owned Analytics](https://developers.google.com/youtube/analytics/channel_reports) is collected at 24h/72h/7d elapsed-age checkpoints, but reports use calendar dates and can lag. These are not exact rolling-hour retention snapshots. Missing stays missing, not zero. Private owned analytics are processed locally, not sent to free Gemini. Competitor private retention/RPM, guaranteed growth, sponsor offers and revenue are not invented. No monetary OAuth scope/revenue collector is implemented.

Public competitor snapshots use the optional YouTube key. `benchmark` ranks discovered videos by public lifetime views divided by age; that is not a current growth rate. Later observations at least one hour apart calculate actual observed public-view deltas. Search relevance is not a census of highest-viewed videos or proof of US audience share. Optional `channels.<profile>.research_queries` lets hourly feed planning collect/rank these references; empty query lists retain feed-only operation. No query is silently selected for the owner. Recent owned reports may be incomplete and are revisited at most every twelve hours until the checkpoint has aged another three days; that delay is a local heuristic, not an API completeness guarantee.

## Batch and browser operating boundaries

Batch flow: saved plan -> renewable batch lease -> recover/create token-bound jobs -> normal pipeline -> checked atomic Resources copies -> hashed manifest. Concurrent starts hold before duplicate creation. A crash between job creation and manifest save can recover the immutable request token. Status reconciles actual jobs and detects changed/missing exports; rerunning repairs copies without re-generating ready jobs. Pause is cooperative between videos. This is a single-PC production queue, not a distributed cluster.

CLI alternatives:

```powershell
.venv\Scripts\python.exe run_pipeline.py --env-file .env batch-run --plan Resources/Plans/prototype-batch.json
.venv\Scripts\python.exe run_pipeline.py batch-status --plan Resources/Plans/prototype-batch.json
.venv\Scripts\python.exe run_pipeline.py generation-plan --kind video --requirements examples/generation-shot.example.json --capabilities examples/generation-capabilities.example.json
```

The capability example is illustrative, not a calibrated Google model profile. `generation-run` defaults to Brave and takes a selectors file plus optional browser config; `--reconcile --apply` only downloads an already-submitted result. A visible previous result blocks a fresh job so it cannot be mistaken for the new output. Attached owner browsers are disconnected rather than closed. A dedicated worker profile closes with its owned browser context; sessions normally persist, subject to Google's expiration/challenges. No autologin, CAPTCHA handling, billing enablement or background launch is added.

Technology tradeoff: Playwright supports precise tested controls and a persistent local profile, but UI changes require calibration and a browser session is broader than an AI Studio API scope.
