# Character speech and background music in chat stories

Implemented 5 November 2026. The message's own character speaks its exact text as the message first becomes visible. Names, timestamps and stage directions are not narrated. Each character has a stable distinct installed voice throughout the story. The existing local Kokoro synthesis/cache and recorded model-license checks are reused; no new speech API, voice clone or visual-generation service is involved.

New chat/phone preview plans enable `chat_voiceover: true` and `chat_auto_music: true`; saved older requests without these settings keep reading-led behavior. New production requests also select and freeze an eligible genre track before writing. See [the music library](MUSIC_LIBRARY_PLAYBOOK.md) for all 14 tracks, licensing and rotation, and [automatic production](AUTOMATIC_PRODUCTION.md) for the upload-ready route. Explicit `music_id` takes precedence over automatic selection. A missing library holds with installation instructions rather than silently downloading or substituting an arbitrary bed.

`chat_voice_ids` optionally maps exact message-speaker names to installed Kokoro IDs. Missing assignments receive distinct IDs from the local default pool. Duplicate voice assignments, unknown speakers and unavailable voices hold. An explicit dad/daughter/mother/unknown mapping is preferable when those names are fixed by a supplied script; the default pool does not infer age, identity or gender from an arbitrary name.

`chat_voice_styles` optionally maps actual speaker names to `natural` or `light_youthful`. The latter applies a small 1.25-semitone pitch/timbre change and 1.03× tempo via the local FFmpeg Rubber Band filter. Only that character changes. The adjusted PCM is cached by input hash and measured before laying out speech. Lily in The Blue Backpack now uses `af_bella` with this style, targeting the owner's requested older-teen register, not claiming a measured age or a cloned human voice. The prior voice and new sample are retained locally for comparison. A build missing that filter holds if a style needs it.

`phone_editor/audio.py` uses the existing licensed synthesis to obtain complete per-message clips. `chat_editing.reading_timing` measures those files and chooses the longer of speech plus a small tail, readable word/character holds and attachment time. Speech starts 0.06 seconds after the bubble appears. A notification already showing the exact message is voiced at that first preview instead; the notification's screen duration is extended through the full line and the later bubble is not voiced again. Event/blackout order and private histories remain intact. The renderer receives that measured event timeline rather than recomputing the old shorter preview.

Optional `chat_pause_before` maps a bubble's message ID to an additional 0-1.5 second anticipation hold. Use it selectively where a setup earns a reversal, not before every reply. The final reply already gets a modest typing delay and extra landing time. Exceeding the format cap holds the job; the editor does not cut speech or silently remove reading time. The [writing skill's timing reference](../src/yt_pipeline/skills/short-video-writing/references/timing.md) distinguishes comic/mystery rhythm from measured audio.

Music is decoded from an eligible registered asset, normalized to a bounded working bed and mixed quietly with smooth ducking to 40% of its configured level during speech. `chat_music_volume` defaults to 0.20 after the source normalization, with a maximum of 0.35; catalog raw-gain suggestions use a different baseline and should not be treated as LUFS. The bed has a short opening/ending fade and dips into/out of actual silent blackouts. One quiet original arrival cue remains; there is no repeated typing chirp. The compositor receives the complete mixed track and does not add the same music twice. Its provenance includes the actual soundtrack, and packaging retains all required credits.

New preview and production requests enable `chat_sound_library`. Twelve deterministic original cues install locally without network calls. The editor uses exactly one arrival or notification cue per message and adds short transition/battery/glitch sounds for the actual compiled events. It mutes blackouts after all tracks are mixed. The four licensed ambience recordings are opt-in via explicit `chat_sound_events`; the writer cannot invent an environment or force an audio URL. Older jobs keep the original soft-pop mix. See the [catalog](MUSIC_LIBRARY_PLAYBOOK.md) for usage and limits.

Three supplied scripts were rebuilt with distinct voices, genre music and provided content-specific titles/descriptions. They remain local test-only candidates, not public uploads or evidence of autonomous Gemini writing quality. Local TTS gives character distinction, not guaranteed acting, sarcasm or emotional delivery. Exact text, decoded PCM, source hashes and technical QA do not establish subjective listening approval.
