# Request and configuration examples

These filenames remain stable because code/tests/documentation use them. They are technical examples, not all production-ready channel briefs. Read [category creation guides](../docs/categories/README.md) for current content instructions and [the walkthrough](../docs/CODE_WALKTHROUGH.md) for contracts.

| Example | Purpose and missing inputs |
| --- | --- |
| [chat-request.json](chat-request.json) | Supplied fictional chat brief/script for contract/integration tests; actual eligible background still needed |
| [education-request.json](education-request.json) | Historical supplied Python-documentation lesson fixture; not the approved education channel topic/style; dated source freshness matters |
| [composition-job.example.json](composition-job.example.json) | Direct compositor recipe; replace missing input paths with actual files |
| [generation-browser.example.json](generation-browser.example.json) | Browser connection configuration shape; not a verified live account connection |
| [generation-shot.example.json](generation-shot.example.json) | Shot requirements for the setting planner |
| [generation-capabilities.example.json](generation-capabilities.example.json) | Illustrative supported model/settings capabilities; calibrate actual provider controls before live use |

Do not add credentials or personal media to examples. A provided script is labeled `provided_script`; it does not become evidence of live Gemini generation. Completed immutable plans and their artifacts belong in Resources/private runtime state, rather than being copied into these examples as competing definitions.
