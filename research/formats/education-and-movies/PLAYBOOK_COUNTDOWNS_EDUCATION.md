## Education findings from actual public video frames

Thirteen education Shorts have actual frame audits: seven initial Jeff Su/Vinh Giang references, four Ali Abdaal references and two further Jeff Su AI tutorials. All thirteen have three-position evidence after successful opening retakes. Specific records and URLs are in the inventory. A 6.6M-view provocative resume example sits alongside 16K-63K-view examples with related editing grammar; copying that grammar cannot guarantee the same result.

The repeatable unit is **one concrete question or mistake, a visible demonstration, and a delivered takeaway**. Jeff Su switches between a real presenter, a viewer question and real document/screen evidence. Vinh Giang demonstrates behavior with an actual speaker/body and crops rather than using random unrelated stock. Text changes with speech and often emphasizes a few words. These observations support purposeful visual matching, not compulsory cuts every two seconds or a compulsory gameplay panel.

## Proposed education format: show the difference

- 0-2s: show the specific before/after, mistake or question immediately. No generic stop-scrolling command.
- 2-7s: define the one task and what result will be shown.
- 7-25s: demonstrate two or three observable actions using actual screen capture, original example text or relevant licensed stock.
- 25-35s: show the changed output side by side and explain the one useful distinction.
- Optional final 2s: ask a genuine related question after the payoff.

The times and initial 155-180 words/minute voice range are **production hypotheses**, not measured rates from these muted browser samples. Keep the accepted male voice for this series; provide a slower setting for complex demonstrations. A self-contained 25-second explanation can be preferable to padding to 45 seconds.

## Writer contract: practical education

Gemini receives the topic, actual source excerpts, one audience problem, allowed facts and available demonstration inputs. It must return original text with stable unit IDs, a narrow promise, a visible payoff, brief captions and precise visual requirements. Reject fake tool capabilities, fabricated hiring/earnings outcomes and screenshots that pretend an action was performed. A resume rewrite must not invent achievements. A dated tool feature needs a current primary source or a fresh actual test.

## Separate director pass

The implemented order is **Gemini writer -> Gemini director with the frozen script and unit IDs -> local TTS measures timing -> asset/template binding -> render**. The director receives the script, selected playbook, available asset inventory and exact editor capabilities; it does not receive measured voice durations. It maps existing units to supported asset queries/IDs, framing, motion, cast and bounded pause/cue instructions. It must not paraphrase, merge, drop or reorder dialogue, change speakers, fabricate timestamps, output code or invent file paths. Local TTS runs after this plan, and the program binds the resulting measured unit durations to assets and captions. Missing media becomes an acquisition request or a hold, never an unrelated random substitute.

## Interactive movie countdown: machine principles and implementation boundary

Choose one narrow theme, give each recommendation an original reason and show readable rank/title/year. If the format offers nine picks plus an audience number one, say that in the opening. A guess-the-film round can show authorized clues and invite an answer, but must not promise an answer at the end and then withhold it. Give the list value first. Posters, GIFs and clips need their own usable basis; the presence of a movie on a list is not permission to download its footage.

The completed visual ledger below covers thirteen education Shorts and ten movie Shorts, plus one opening-only movie challenge. The implementation currently includes a voiced movie_countdown playbook and a movie_cards identifier bound to a single-source ranked stock preset. Faster silent cards, simultaneous poster-plus-still panels, full poster carousels and dedicated quiz/timer layouts remain proposed variants, not completed specialized renderers.

## Concrete 33-second education beat plan

Proposed example task: repair an overly vague application bullet. All candidate experience remains hypothetical and must reflect the applicant's real work. This example is an original format sketch, not copied dialogue from a reference.

| Unit / target window | Spoken purpose | Specific visible state | Editor action |
| --- | --- | --- | --- |
| u01 / 0-2.5s | Specific problem: a line gives the reader nothing concrete to picture | A mock résumé; highlight only the vague line | Full-width document crop, immediate highlight |
| u02 / 2.5-5s | Promise one truthful repair, rather than a job guarantee | Before/after labels with the after still blank | Hold document; short caption, no giant heading |
| u03 / 5-8s | Identify the action actually performed | Highlight the real action phrase | Punch into that region |
| u04 / 8-11s | Identify who or what benefited | Show a second underlined phrase | Move focus inside the same document |
| u05 / 11-15s | Show an observable result only if the applicant can verify it | An optional result field explicitly marked use only if true | Hold long enough to read |
| u06 / 15-19s | Assemble a clearly labeled illustrative sentence | Reveal the revised line, not fake typing loops | Cut to clean after card |
| u07 / 19-24s | Explain the difference in one sentence | Before and after simultaneously | Side-by-side comparison |
| u08 / 24-29s | Give a portable check: can a reader picture the work? | Three small labeled elements: action, context, evidence | Simple annotation; avoid busy unrelated stock |
| u09 / 29-33s | End on the completed contrast; optional relevant question | After line remains readable | Hold and subtle final caption |

These are target durations only. After the writer and director passes, local TTS synthesizes the accepted voice and measures its actual length per unit. Asset/template binding then solves cut timing from those measurements. A larger word count does not automatically fit 33 seconds. For AI tool clips, use the same structure but replace the document repair with input, action, actual output and one limitation that materially affects use.

## Practical writing rules for Gemini

1. Pick one audience situation with a useful result, not a topic such as productivity in general. The hook points at the visible artifact, contradiction, mistake or test.
2. Generate three different **specific** hook candidates internally. Choose the one that the available result actually fulfills. Generic commands to stop scrolling are optional and usually expend time without stating a benefit.
3. The opening promise, body demonstration and payoff must concern the same question. Never swap the promised answer for follow-for-part-two or ask for comments to unlock it.
4. Use one sentence per stable unit. Give each unit a single useful function and a corresponding visual subject. During a demonstration, a new crop/highlight/output state can provide change without replacing the whole background.
5. The narrator may sound direct and confident; certainty must not exceed the evidence. Explain an action people can try rather than a guaranteed job, income, health or memory outcome.
6. Tool features, pricing, quotas, job listings and eligibility are current facts: the researcher supplies dated official evidence. If missing, return a hold/request for evidence; do not invent a click path or job opening.
7. Confidence and study tips may vary by person. A simple method can be offered clearly without claiming that everyone succeeds or hiding a material limitation.
8. Copy the structural lesson, not a creator's sentences, identity, footage or personal success story. A real success story needs verifiable biographical facts and cannot imply that an exceptional case is a typical outcome.
9. Every factual statement has a supplied claim ID; every illustrative scenario is clearly identified as an example. The claim record stores source URL and retrieval date. Stock people are illustrations, not testimonials.
10. Captions support the narration in short readable phrases. Keep small captions out of essential UI/text; emphasize one relevant phrase rather than painting the whole screen.

## Stage A: proposed frozen-script prompt

This is a reusable prompt specification. The production source of truth is `src/yt_pipeline/playbooks.py` together with the provider's script schema; do not paste this prose as a competing JSON schema.

```text
You are the writer for an original practical-education Short.
Inputs: selected topic and audience situation, education_demo playbook,
verified claims with IDs, known usable asset inventory, supported editor capabilities.

Write only the content script first. Choose one narrow visible problem,
demonstrate one real action/example and deliver the promised answer/result.
Do not write editing instructions into spoken text. Do not invent URLs,
app screens, free features, earnings, jobs, credentials or personal tests.
Use 7-12 stable unit IDs (u01...) and one exact speaker for every unit.
The hook names the specific observable problem, not an unrelated fear.
Return a clear opening_promise and the unit that fulfills it before any CTA.
Each factual unit references only supplied claim IDs.
If evidence or an essential demonstration is unavailable, request it instead
of writing around it with stock footage or unsupported claims.
Follow the supplied runtime/word bounds; actual TTS duration is measured later.
Choose a natural relevant question only after delivering the result.
Output only the application's supported script JSON, no markdown.
```

## Stage B: bounded director prompt and handoff

```text
You are the director. The input script has already been approved/frozen.
Preserve every unit ID, text byte-for-byte, order and speaker. Do not repair
weak writing by paraphrasing, moving, adding or dropping lines. If the story
or explanation does not deliver its opening promise, return a review hold.

For each unit choose an available asset ID or a bounded asset search request,
its visible subject, background, framing, supported motion and optional cue.
Match the shown action/diagram/document to what that exact line says.
Reuse locations for continuity; change focus when the information changes.
Use only the provided capabilities, voices and registered media IDs.
No guessed asset IDs, paths, URLs or soundtrack files. A request is not an asset.
Use no personal testimonial imagery or fake app evidence.
Mark required footage as missing when none is supplied; do not substitute
random attractive footage and claim the required demonstration is complete.
Reference unit IDs for time; do not fabricate timestamps. The director runs
before voice synthesis. Local TTS subsequently measures the audio and pauses,
and asset/template binding resolves them into timestamps and caption intervals.
Return only the application's supported creative-plan JSON.
```

The current `creative_plan.py` recognizes template identifiers including `education_demo` and `movie_cards`; those names do not imply a dedicated renderer for every research layout. The present movie route uses the shared single-source stock renderer: one selected still or source clip per unit, with captions; the still path can also show the validated rank plate. It does not simultaneously compose a separate poster and movie still. Its ordinary scene vocabulary is wide/medium/closeup framing and hold/slow_push/punch/pan_left/pan_right motion. Cast assets may be cat, dog, human or narrator. Closeup can hide the other cutouts and enlarge the focus character. It does not offer a general-purpose After Effects timeline, realistic character rigging, lip sync, automatic current-app recording, unlimited arbitrary transitions or cinematic acting from a static image. Searches need an acquisition stage and permission/quality checks before becoming usable assets. Director emotion tags are guidance, not evidence that a TTS model can perform that emotion.

A useful additional edit contract for later expansion would record `semantic_role`, `claim_ids`, `readable_region`, `crop_region`, `required_asset_kind` and `missing_asset_action` per unit. These fields are proposals, not assumed current schema keys. Current source validation must reject unsupported keys rather than silently pretending the editor acted on them.

### Template A: nine picks and your number one (current ranked-preset structure)

Opening explicitly says nine suggestions plus the viewer's own top pick. Count from 10 to 2, with a theme narrow enough that every title earns its place. Each card contains a readable rank, title/year where verified, one original reason to watch and an image/clip the pipeline is permitted to use. A repeated word such as peak is decoration, not the reason. The final unit asks the audience for number one. Keeping all nine titles visible together or supplying a consolidated list is an additional presentation proposal; the current stock preset does not compose that overview automatically.

For a 45-55-second target, budget about 3 seconds for the premise, 4-5 seconds for each of nine cards and 3 seconds for the final choice. That arithmetic requires concise reasons; it is not a measured successful creator pattern. If titles/reasons cannot be read, a proposed five-pick variant would be preferable to an incomprehensible pace. The current validator requires exactly nine ranked picks from 10 to 2; a five-pick variant needs its own supported preset/validation change. A quiet licensed rhythmic instrumental is sufficient; famous movie scores are not included by default.

### Template B: complete countdown (proposed separate variant)

If the opening promises the best film or a number-one reveal, deliver number one. Discussion can follow: ask which placement viewers disagree with. Make it clear that this is the channel's editorial ranking, unless a specified dated external metric actually determines the order. Do not call personal favorites objectively highest rated or trending without supporting data.

### Template C: explicit guess round (proposed separate variant)

Label it a guess-the-film challenge at the start. Give an authorized visual clue or an original text/diagram clue with enough information to make a fair guess. Reveal the answer after a short think interval, or clearly say that this particular open challenge invites guesses and provides the answer in a visible pinned follow-up prepared by the publisher. Do not promise an in-video answer and then omit it. Preserve required credits even when the title is intentionally hidden for a quiz. Never use missing attribution as the engagement mechanism.

### Machine inputs and holds

A movie item needs `rank`, `canonical_title`, `year`, `original_reason`, `verified_fact_ids` and `permitted_asset_id` in the data model or acquisition request. The director schema already supports `rank` and a constrained `display_title`; the remaining enriched item fields are proposed data requirements, not assumed current script-schema keys. Count ranks for duplicates/skips; validate every card has a different relevant asset; ensure no title is accidentally hidden in a recommendation. Movie posters, copyrighted GIFs, clips and music are independent rights layers. Public availability, a creator's apparent non-enforcement or a successful competitor's usage is not a permission record. A graphic built from original text/diagrams is a valid fallback when permitted film material is absent; random character imagery is not.

## Runtime review and controlled tests

Before rendering, verify exact script preservation, claim/source coverage, all required media present, distinct useful visual states, required music registration and actual voice duration. After rendering, inspect opening, demonstration, payoff and caption readability at phone size. The reviewer must be able to identify the promised result and point to where it appears. A model's own boolean review is an aid, not a human or independent factual check.

Start with a small prototype per family. For education test artifact-first versus problem-first hooks on different original examples; for movies, once the separate preset exists, test complete five-pick versus the currently supported nine-plus-viewer-choice packaging. Compare matched topic/age cohorts when practical. Monitor viewed-versus-swiped-away, average percentage viewed, completion/rewatches and substantive comments from the channel's own analytics, along with negative feedback. Avoid claiming an edit caused growth from one upload. A method is retained only when actual audience results and production quality justify it.

### Three movie variants, with different production needs

**Fast card edit, proposed 12-24s:** a narrow theme, five to nine permitted poster/still items, readable film title and a few words of original rationale, permitted music, no required voiceover. New item on a clean cut; a brief punch/blur can bridge selected items. A card must remain readable at phone size. The ten-to-twenty-second source runtimes establish that short montages exist; they do not establish an exact optimal dwell time or actual full-item count. Choose fewer picks if the title/reason cannot be read. A machine preset should explicitly set `voice_required=false`; it should not manufacture 90 words of narration merely because the existing lesson schema expects speech.

**Voiced useful list, current target 35-55s:** the implemented movie_countdown playbook requires nine ranked picks from 10 to 2 and an upfront invitation for the viewer's number one. Its current movie_cards binding uses one stock source per unit with captions/rank treatment, not the simultaneous poster/still composition. Show what each original reason refers to and complete the promise. A complete five-pick list is a proposed separate variant requiring a validation/preset change. The current 75-135-word requirement fits this richer voiced format better than the fast poster examples.

**One-film emotional reveal, proposed 10-20s:** opening establishes a specific taste or feeling; ending names the film and shows a relevant permitted poster/still. Useful for a narrow recommendation, not a list that exists only in its title. No need to manufacture a ranking or add gameplay.

A future template configuration can select `poster_full`, `poster_above_still_below` or `film_clip_with_title` with a central reason/title band. These are proposed rendering variants, not assumed implemented schema fields. The existing movie_cards template must explicitly support each layout before a director can request it.

### Movie writer/director additions

For a fast format, the writer produces an opening theme, ordered canonical item titles, very short original reasons and a delivered closing state. Factual extras use supplied claims; no invented awards, streaming availability, plot facts or ratings. In the proposed fast-card variant, the director would map each item to actual supplied media, safe crops and text positions using that variant's explicitly implemented capabilities. It may not put two different films under one title or use an unrelated glamorous clip to suggest the selected movie contains it. A blank/missing asset produces an acquisition hold or an original text-based graphic, according to the chosen supported fallback.

For an interactive round, explicitly distinguish a ranking opinion from a quiz with a correct answer. A genuine choice question is useful after the viewer has received something: which omitted movie earns your number one, which criterion matters most, or which clue gave away the answer. A promise that the best item will be revealed requires that reveal. None of the observed view counts establishes that withholding a title causes engagement, nor that a clip/poster channel is automatically monetizable.
